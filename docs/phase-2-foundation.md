# المرحلة 2 «الأساس» — الدفعة الأولى

> المرجع: [كراسة المواصفات](spec/trend-technical-spec.md)، القسم 15.1.

## لماذا نبدأ من المرحلة 2

المرحلة 1 «التشخيص والتصميم» مخرجاتها أعمال تحليلية مع ترند (خريطة الهيكل، خرائط العمليات،
نظام التصميم بالهوية، النماذج الأولية، اختيار الاستضافة والتفريغ) وبوابتها اعتماد ترند للنطاق.
لذلك يبدأ البناء البرمجي من المرحلة 2، مع ترك كل ما يعتمد على مخرجات المرحلة 1 قابلاً
للاستبدال دون تغيير الكود (الهوية البصرية، مزود الاستضافة).

بوابة المرحلة 2: **اختبارات الصلاحيات وعزل المستأجرين ناجحة 100%**.

## قرارات اتُّخذت افتراضياً (للمراجعة)

1. **إصدار الرموز والمصادقة الثنائية مؤجلان للدفعة التالية.** الخادم يتحقق الآن من رمز وصول JWT
   قصير العمر (15 دقيقة، §8.1)، والدور يُقرأ من العضوية في كل طلب لا من الرمز. الكراسة تذكر
   «Better Auth أو Keycloak»؛ التوصية Better Auth لأنه TypeScript داخل الخادم نفسه ويدعم TOTP
   وSSO دون خادم هوية منفصل يُشغَّل.
2. **الترحيلات بملفات SQL مكتوبة يدوياً** مع مرآة أنواع Drizzle، لأن RLS والمشغّلات وسلسلة
   التجزئة لا تُعبّر عنها أدوات التوليد بوضوح. لا يُعدَّل ترحيل طُبّق (يُكشف بالـ checksum).
3. **الهوية البصرية** (سؤال مفتوح في 17.3): ألوان محايدة وخط IBM Plex Sans Arabic، تُستبدل من
   `packages/ui/src/tokens.ts` وحده.
4. **مزود الاستضافة** (17.3): لا شيء في الكود مرتبط بمزود؛ PostgreSQL 17 مع pgvector في الحاويات.
5. **الأرقام**: الغربية (012) افتراضياً لكل مستخدم، والعربية (٠١٢) خيار في إعداداته.
6. **العضو لا ينشئ مشاريع افتراضياً** («قابل للضبط» في §9.1)، ويرسل الاتصال التنبيهي افتراضياً.
   كلاهما في `workspaces.settings.memberPolicy`.
7. **استثناءات فحص التبعيات** (`pnpm.auditConfig` في `package.json`): خمس ثغرات كلها داخل أدوات
   بناء Expo/Metro (node-forge، braces، image-size، sprintf-js) لا في ما يُشغَّل للمستخدم، أربع منها
   بلا إصلاح منشور، وإصلاح image-size يكسر واجهة Metro. تُراجع مع كل ترقية لـ Expo.

## المتبقي من المرحلة 2

- وحدة الهوية: تسجيل الدخول، Argon2id، رمز التجديد الدوّار، TOTP الإلزامي للمالك والمشرفين،
  القفل بعد 5 محاولات، الأجهزة النشطة، SSO مع Google وMicrosoft (§9.2).
- الملفات: تخزين S3 بروابط موقّعة، فحص ClamAV، جدول `files`.
- الاستيراد الجماعي من CSV وإرسال بريد الدعوة (FR-ORG-03).
- العامل الخلفي لتوزيع صندوق الأحداث (§5.2) بدور مستقل.
- OpenAPI 3.1 مولّد من الكود، وحدود الطلبات، وIdempotency-Key وIf-Match (§8.1).
- بيئة المعاينة لكل PR والنشر للتجريبية (§12.4).

## التشغيل المحلي

```bash
cp .env.example .env && set -a && . ./.env && set +a
docker compose up -d postgres
pnpm install
pnpm build
pnpm db:migrate
pnpm --filter @trend/api seed           # يطبع tenantId وownerUserId
pnpm --filter @trend/api dev:token <ownerUserId> <tenantId>
pnpm --filter @trend/api start          # http://localhost:4000/api/v1/health
pnpm --filter @trend/web dev            # http://localhost:3000
```

الاختبارات تحتاج PostgreSQL مع pgvector، وتنشئ قاعدة مؤقتة لكل ملف وتحذفها:

```bash
DATABASE_ADMIN_URL=postgres://trend_owner:trend_owner@localhost:5432/trend pnpm test
```
